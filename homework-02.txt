# Upgrade students_base: Django 1.7.1 → 6.0.7, DRF 2.4.3 → 3.17.1, Python 2 → 3.14

## Context

The project is pinned to Django 1.7.1 / DRF 2.4.3 and written for Python 2. It cannot run at all — the
in-tree `.venv` is CPython 3.14.6. We want it on current versions: **Django 6.0.7, DRF 3.17.1,
Python 3.14** (Django 6.0 supports 3.12–3.14, so the existing venv interpreter is the right target; all
three versions confirmed as latest on PyPI).

Big-bang upgrade rather than stepwise: the app is ~1500 lines, `db.sqlite3` is gitignored, and there is
no production data. Two front ends must both work afterwards:

- server-rendered Django CBVs (`base/views.py` + `base/templates/`)
- the AngularJS 1.3 SPA (`static/angular/`), which hard-depends on the current API contract

**Non-goals:** rewriting the SPA, changing the API response envelope, adding pagination, or modernizing
the karma toolchain. The SPA's controllers read `data.data.*` and iterate bare arrays, so DRF's default
pagination would silently blank every table.

**Much of the suite is already red before we start** — the duplicate `api:auth` URL name routes the auth
tests to the token view (wrong envelope), and session login + token-only DRF auth 401s every CRUD test.
Getting `manage.py test` green is part of this work, not a regression to avoid.

Decisions confirmed with the user: squash migrations; drf-spectacular; enable Session **and** Token auth;
fix pre-existing bugs that make a page/endpoint outright fail; make the SPA reachable at a prefix; port
`base/middleware.py` to the new style rather than delete it.

## Phase 2 — URLconfs

**`students_base/urls.py`** — full rewrite. `patterns()` (removed 1.10), `url()` (removed 4.0), string
view references (removed 1.10), `include(admin.site.urls)` (invalid 2.0+), and `namespace=` without
`app_name` (error 2.0+) all have to go, plus `admin.autodiscover()` and `from base.views import *`.

```python
from django.contrib import admin
from django.contrib.auth import views as auth_views
from django.urls import include, path, re_path
from django.views.decorators.csrf import ensure_csrf_cookie
from django.views.generic import TemplateView

from base import views as base_views

urlpatterns = [
    path('admin/', admin.site.urls),

    path('api/v1/', include('api.urls', namespace='api')),
    path('ang/api-auth/', include('rest_framework.urls')),  # no namespace= — DRF sets app_name itself

    path('groups/', base_views.GroupList.as_view(), name='group_list'),
    path('groups/add/', base_views.GroupAdd.as_view(), name='group_add'),
    path('groups/edit/<int:group_id>/', base_views.GroupEdit.as_view(), name='group_edit'),
    path('groups/delete/<int:group_id>/', base_views.GroupDelete.as_view(), name='group_delete'),
    path('groups/<int:group_id>/', base_views.StudentList.as_view(), name='student_list'),

    path('student/add/', base_views.StudentAdd.as_view(), name='student_add'),
    path('student/edit/<int:student_id>/', base_views.StudentEdit.as_view(), name='student_edit'),
    path('student/delete/<int:student_id>/', base_views.StudentDelete.as_view(), name='student_delete'),

    path('login/', auth_views.LoginView.as_view(
        template_name='registration/login.html'), name='login'),
    path('login_email/', auth_views.LoginView.as_view(
        template_name='registration/login_email.html'), name='login_email'),
    path('logout/', auth_views.LogoutView.as_view(next_page='group_list'), name='logout'),

    # AngularJS SPA shell (html5Mode). ensure_csrf_cookie because every DRF APIView
    # is csrf_exempt and index_angular.html has no {% csrf_token %}, so nothing would
    # ever set the csrftoken cookie the SPA needs for X-CSRFToken.
    re_path(r'^app/', ensure_csrf_cookie(
        TemplateView.as_view(template_name='index_angular.html'))),

```

**Why `/app/` and not the original catch-all `^.*$`.** `app.js` routes `/groups` and `/groups/:groupId`,
which collide head-on with the server-rendered `group_list`/`student_list` — that is almost certainly why
the route was commented out. Mounting at `/` means one front end shadows the other. `/app/` keeps both,
and requires `<base href="/app/" />` in `index_angular.html` (Phase 5); Angular's html5Mode strips the
base, so the existing `$location.path('/groups')` calls and relative links keep working unchanged.

`redirect_field_name: 'groups/'` is dropped — it names the *query parameter*, not the redirect target, so
it was always a misuse; `LOGIN_REDIRECT_URL` covers the intent. `next_page='group_list'` on `LogoutView`
works as-is (`resolve_url` reverses a bare name with no `/` or `.`).

**`api/urls.py`** — full rewrite with `path()`, plus `app_name = 'api'` (now required by the
`namespace='api'` include) and the drf-spectacular routes. Three bug fixes ride along:

- **The duplicate `name="auth"`** — `auth-token/` becomes `name='auth-token'`. This is load-bearing:
  `reverse("api:auth")` in `AuthenticationTastCase` currently resolves to `LoginTokenView`, so those five
  tests assert `data["status"]` against a `{"success": …}` envelope and fail. Renaming points them at
  `LoginView`, which is what they were written for.
- `studets-detail` typo → `student-detail`. Grepped: nothing reverses it (tests never use it; the SPA
  hardcodes URL strings), so the rename is safe.
- Remove the `rest_framework_swagger.urls` include; add
  `path('schema/', SpectacularAPIView.as_view(), name='schema')` and
  `path('docs/', SpectacularSwaggerView.as_view(url_name='api:schema'), name='docs')`.
  This also consolidates today's *two* separate `/docs/` mounts into one.

**New `base/apps.py`** — `BaseConfig(AppConfig)` with `default_auto_field`, `name = 'base'`, and a
`ready()` that does `from base import signals  # noqa: F401`.

**`base/models.py`**
- `__unicode__` → `__str__` on `Department`, `Group`, `Student`.
- Add the now-required `on_delete`: `department = models.ForeignKey("Department", on_delete=models.CASCADE)`
  and `group = models.ForeignKey("Group", on_delete=models.CASCADE)`. CASCADE matches the behavior
  `CLAUDE.md` documents. `headman` already has `on_delete=models.SET_NULL`.
- Delete the four `post_save.connect(...)`/`post_delete.connect(...)` lines at the bottom and the
  `from base.signals import ...` import.
- **Move `LogEntry` here and delete `base/signal_models.py`.** It was only ever registered as a side
  effect of the `models.py → signals.py → signal_models.py` import chain; once signals move to `ready()`
  that chain is gone and the model would silently vanish from the app registry. The table name derives
  from `app_label` + model name, so `base_logentry` is unchanged. Replace the
  `get_action_status()` string→int reverse lookup with `ADD, CHANGE, DELETE = 1, 2, 3` constants, and
  `__unicode__` → `__str__`.

**`base/admin.py`** — `from base.signal_models import LogEntry` → `from base.models import ...`.

**`base/signals.py`** — rewrite with `@receiver` using lazy `sender='base.Group'` string senders and
`dispatch_uid` for idempotency, writing `object_descript=str(instance)`. Two bugs fixed: the current code
assigns a **model instance** to a `TextField` (relying on implicit coercion, which produces
`Group object (1)` garbage until `__str__` exists), and `kwargs['created']` is unguarded.

**`base/auth.py`** — `MyAuth.authenticate` is missing the `request` positional argument, so modern
Django's backend-signature inspection never calls it. Rewrite as a `ModelBackend` subclass, keeping the
class name so the settings string is untouched:
```python
class MyAuth(ModelBackend):
    """Authenticate by email address instead of username."""

    def authenticate(self, request, username=None, password=None, **kwargs):
        UserModel = get_user_model()
        if username is None:
            username = kwargs.get(UserModel.USERNAME_FIELD)
        if not username or password is None:
            return None
        try:
            user = UserModel._default_manager.get(email__iexact=username)
        except UserModel.DoesNotExist:
            UserModel().set_password(password)   # equalize timing
            return None
        except UserModel.MultipleObjectsReturned:
            return None
        if user.check_password(password) and self.user_can_authenticate(user):
            return user
        return None
```
The `if not username` guard is not theoretical: `fixtures/auth.json` contains a user with
`email: ""` (pk 4, `headman_user`), and `User.email` is not unique. Inheriting `ModelBackend` supplies
`get_user()` (delete the hand-rolled one) and `user_can_authenticate()` — the inactive-user check the old
backend lacked. Drop the unused `from django.conf import settings`.

**`base/forms.py`** — `GroupForm.__init__` calls `self.instance.student_set.all()`, which raises
`ValueError` on an unsaved instance since 1.8, breaking admin → Groups → **Add**
(`GroupAdmin.form = GroupForm`). Guard it:
```python
if self.instance.pk:
    self.fields['headman'].queryset = self.instance.student_set.all()
else:
    self.fields['headman'].queryset = Student.objects.none()
```

**`base/views.py`**
- `from django.core.urlresolvers import reverse` → `from django.urls import reverse` (removed 2.0).
- All `super(X, self)` → `super()`.
- **`GroupAdd`: `fields = ['name']` → `fields = ['name', 'department']`.** `Group.department` is a
  non-null FK, so server-rendered "add group" has never been able to work — it dies on `NOT NULL`.
  Also replace `@method_decorator(login_required(login_url='/login'))` on the pass-through `dispatch`
  with `LoginRequiredMixin` (which also fixes the missing trailing slash on `/login`), and drop the now
  unused `method_decorator`/`login_required` imports.
- **`GroupEdit`: delete the `fields = ['name', 'headman']` line**, keep `form_class = GroupForm` —
  specifying both is `ImproperlyConfigured` since 1.8.
- **`StudentAdd` and `StudentEdit`: add `fields = ['fio', 'birthday', 'number_student_cart', 'group']`** —
  a `model` with neither `fields` nor `form_class` is `ImproperlyConfigured` since 1.8.
- `StudentAdd.get_context_data` does `self.request.GET['group_id']` → 500 on a missing param. Use
  `.get('group_id')`, and add a `get_initial()` that pre-selects the group when the param is present.
- `StudentList`: delete the dead pass-through `dispatch`, and replace `get_list_or_404` (which 404s an
  *empty* group) with `get_object_or_404(Group, pk=...)` + `group.student_set.all()` — 404 for a
  nonexistent group, empty table for an existing-but-empty one. `student_list.html` already guards with
  `{% if student_list %}`.
- `GroupDelete`/`StudentDelete` need no change beyond `super()`: Django 4+ `DeleteView` computes
  `success_url` before deleting, so `self.object.group.pk` is still valid.

**`base/management/commands/get_groups.py`** — remove `can_import_settings = True` (obsolete
`BaseCommand` attribute), write via `self.stdout.write(...)` instead of returning a string, drop `u''`
prefixes.

**`base/middleware.py`** — port to the new style (per the user's choice) and leave it commented out of
`MIDDLEWARE`. It needs a `__init__(get_response)` / `__call__` pair, and its
`response.content.replace('</body>', …)` must decode/encode with `response.charset` — today it's a

## Phase 6 — DRF API layer

**`api/serializers.py`**
- `SerializerMethodField('method_name')` — the positional method-name argument was removed in DRF 3
  (5 occurrences). Drop it and rename to the `get_<field>` convention: `count_group_fun`,
  `count_student_fun` (**on two serializers, different bodies**), `avg_age_fun`, `headman_name_fun`.
- **`get_age` must keep its name** — `api/tests.py::test_get_age` instantiates `DepartmentSerializer()`
  and calls `.get_age(date)` directly. There is no field named `age`, so DRF won't mistake it for a
  method field.
- Simplify `get_count_student` on `DepartmentSerializer` from the per-object
  `Department.objects.annotate(Count(...)).get(pk=obj.pk)` re-query to
  `Student.objects.filter(group__department=obj).count()` — same number, one cheap query. Keep the
  `int(...)` truncation in `get_avg_age` (the SPA spec's float expectation is a pre-existing mismatch,
  handled in Phase 8).
- **`get_headman_name` returns `obj.headman`, a `Student` model instance.** DRF 2 coerced it via
  `force_text`; DRF 3 hands it straight to the renderer → `TypeError: Object of type Student is not JSON
  serializable` on *every* group list/detail response. Fix:
  `return str(obj.headman) if obj.headman_id else None` (renders as empty in Angular interpolation, which
  is what `views/group_list.html`'s `{{ group.headman_name }}` wants).
- **The `headman: ''` problem.** `controllers.js:242,310` send an empty string for "no headman". DRF 2
  coerced `''` → `None` for a nullable FK; DRF 3's `PrimaryKeyRelatedField` rejects it, so SPA group
  add/edit breaks. DRF's built-in `'' → None` rule only fires for *form-encoded* input via
  `Field.get_value()`, and the SPA posts JSON — so a field subclass is needed:
  ```python
  class EmptyStringAsNullPKField(serializers.PrimaryKeyRelatedField):
      def to_internal_value(self, data):
          if data == '' or data is None:
              return None
          return super().to_internal_value(data)

  class GroupSerializer(serializers.ModelSerializer):
      headman = EmptyStringAsNullPKField(
          queryset=Student.objects.all(), allow_null=True, required=False)
  ```
  `allow_null=True` is what lets `''` reach `to_internal_value` (`validate_empty_values` only
  short-circuits on `None`); `required=False` covers both `GroupAdd`'s first POST and
  `test_post_group_success`, which omits `headman` entirely. Output stays an integer pk, so the read
  contract (`GroupEdit` matching `students[i].id == group.headman`) is unchanged.

**`api/views.py`**
- `model = Department/Group/Student` on the three `RetrieveUpdateDestroyAPIView`s (lines 34, 64, 88) —
  the `model` shortcut was removed in DRF 3. Replace with `queryset = X.objects.all()`.
- `self.request.QUERY_PARAMS` → `.query_params` (lines 52, 76).
- `request.DATA` → `request.data` (lines 105, 106, 149, 150).
- `unicode(...)` → `str(...)` (lines 124, 125, 171, 172).
- `authenticate(username=…, password=…)` → `authenticate(request, username=…, password=…)` in both
  `credentials()` helpers — required by the modern backend signature.
- `if (request.user == AnonymousUser())` → `if not request.user.is_authenticated` (a property, not a
  method, since 1.10). `str(request.user)` still yields `"AnonymousUser"`, so the test assertions hold.
- **`Token.objects.create(user)`** (line 161) passes a `User` positionally to a manager `create()` →
  `TypeError`, and `Token.user` is a `OneToOneField` so a second login would `IntegrityError`. This
  endpoint is broken today. Fix: `token, _ = Token.objects.get_or_create(user=user)`.
- `super(X, self)` → `super()`; delete the commented-out `SessionAuthentication` import block and the
  dead `#username = request.DATA.get("username")` line.
- Leave `permission_classes = ()` on `LoginView` and `authentication_classes = () / permission_classes = ()`
  on `LoginTokenView` — that's what lets anonymous login past the global `IsAuthenticated`.

**`api/mixins.py`** — both envelope shapes must stay byte-for-byte identical. Collapse the duplication by
making `ResponseDataWrapperMixinSuccess` subclass `ResponseDataWrapperMixin` with class-attribute
overrides (`envelope_key`/`success_value`/`fail_value`), and replace the hardcoded status tuples with
ranges (`2xx` → success, `4xx` → fail, everything else unwrapped). This drops the non-standard `480`,
picks up 2xx/4xx codes the tuples missed, and keeps 5xx unwrapped — necessary, because an unhandled
exception produces a response with no `.data`.

**204 caveat:** DELETE responses will still carry a wrapped body with a 204 status, which is technically
invalid HTTP. `api/tests.py:234-235` asserts exactly that (204 **and** `data["status"] == "success"`),
`.data` is read pre-render, and the SPA ignores delete bodies — so keeping it preserves the contract. If
it turns out to trip something under Django 6, the minimal fix is `if response.status_code == 204: return
response` plus dropping the `status` check in those two assertions. Verify empirically in Phase 9 before
changing anything.

**Docstrings** — the `<pre>{…}</pre>` blocks were swagger-1.x docs. With `Markdown` installed the DRF
browsable API still renders them; drf-spectacular will show them as literal text. Low priority.

## Phase 7 — Fixtures

`fixtures/test_data.json` — no change (2 departments / 5 groups / 25 students; `headman` and `department`
are integer pks or null).

`fixtures/auth.json` — **delete all 30 `auth.permission` rows.** `migrate` auto-creates permissions, and
since Django 2.1 every model also gets `view_*`, so the fixture's hardcoded pks are guaranteed wrong;
loading a row whose `(content_type, codename)` already exists under a different pk is an `IntegrityError`
on the unique constraint.

Then `auth.group` pk 1 (`headman_group`) must stop referencing permission pks `[19, 20, 21]` (verified =
`add/change/delete_group` on `base.group`) and use **natural keys**, which are stable:
```json
"permissions": [["add_group", "base", "group"],
                ["change_group", "base", "group"],
                ["delete_group", "base", "group"]]
```

4. `test_get_age` (238–258) builds `date(day=today.day - 1)` and `+ 1`, so it **raises `ValueError` on

**API contract by hand** (`runserver`, log in at `/ang/api-auth/login/`):
- `GET /api/v1/department/` → `{"status":"success","data":[…]}` — a **bare array**, not `{count,results}`
- `GET /api/v1/group/1/` → `department`/`headman` are ints-or-null; `headman_name` is a **string**-or-null,
  never an object
- `PUT /api/v1/group/1/` with `Content-Type: application/json` and `"headman": ""` → 200, not 400
- `POST /api/v1/auth-token/` **twice** for the same user → 200 both times, `{"success":true,…}`
- `GET /api/v1/department/999/` → `{"status":"fail","data":{"detail":…}}`
- `/api/v1/docs/` renders Swagger UI; `/api/v1/schema/` returns OpenAPI 3. Note the schema will be
  *inaccurate* about response bodies — the envelope mixins rewrite them in `finalize_response`, which
  spectacular cannot see without `@extend_schema` annotations. Accept the rough schema for now.

render an empty table, not 404) → `groups/add/` (the `department` field must be present and saving must
